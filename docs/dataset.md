# Данные и бенчмарк

## 1. Стандарт данных

```
data/
  sources.yaml              # источники = единица разбиения (книга / рукопись / номер газеты)
  benchmark_manifest.csv    # одна строка = одна страница
  wikisource_lock.json      # закреплённые ревизии Wikisource (воспроизводимый GT)
  raw/<source_id>/…         # изображения страниц (НЕ в git, скачиваются скриптом)
  processed/                # производные (НЕ в git)
  ground_truth/<id>.txt                 # GT в арабской графике (построчно, как на странице)
  ground_truth/<id>.modern_tatar.txt    # параллельная современная кириллица (если есть) — для Phase 4
  ground_truth/<id>.json                # происхождение GT: ревизия, автор правки, качество, конверсия
  splits/                   # (зарезервировано для будущих train/val списков)
```

Колонки `benchmark_manifest.csv` (пути — относительно `data/`):

| колонка | значение |
|---|---|
| `id` | `<source_id>_p<NNNN>` |
| `image_path` | `raw/<source_id>/pNNNN.jpg` |
| `source_id` | книга/рукопись/выпуск; **сплиты делаются только по нему** |
| `page` | номер страницы в источнике (PDF/DjVu) |
| `type` | `printed` / `handwritten` |
| `script_style` | `iske_imla_naskh`, `yana_imla_naskh`, (позже: `ruqa`, `nastaliq`, …) |
| `approx_year` | год издания/написания |
| `ground_truth_path` | `ground_truth/<id>.txt` (пусто для неразмеченных) |
| `split` | `train` / `val` / `test` / `unlabeled` |
| `subset` | `core` (≥80% букв — арабица) / `mixed` (много кириллицы) / `photo` |
| `language`, `gt_status`, `license`, `notes` | доп. метаданные |

`gt_status`: `gold_verified` (проверено экспертом) > `silver_proofread` (вычитано на Wikisource) >
`silver_unproofread` (набрано, не вычитано) > `draft_unverified` (машинный черновик) > `none`.

Проверка: `python -m benchmark.manifest validate data/benchmark_manifest.csv` — обязательные колонки,
существование файлов, допустимые значения и **отсутствие одного `source_id` в нескольких сплитах**.

## 2. Текущий бенчмарк (только реальные документы)

Источник страниц — публичные (PD) сканы на Wikimedia Commons; GT — постраничные транскрипции
Wikisource (ProofreadPage), закреплённые по revision id. Сборка: `python scripts/fetch_wikisource_benchmark.py`.

| source_id | книга | год, место | орфография | страниц core / mixed | арабских букв | статус GT |
|---|---|---|---|---|---|---|
| `ws_tatar_maktabe_1915` | Г. Биктави, «Татар мәктәбе. Рәсемле төрки әлифба» | 1915, Оренбург | иске имля (дореформенная) | 5 / 1 | 3 106 | не вычитано (уровень 1) |
| `ws_rus_maktaplare_1925` | М. Корбангалиев, Х. Бәдигый, «Рус мәктәпләре өчен татар теле дәреслеге» | 1925, Казань | яңа имля (реформированная арабица) | 9 / 22 | 11 129 | 2 стр. вычитаны, остальные — нет |
| `ws_tatarcha_uryscha_1927` | Корбангалиев, Газизов, Кулиев, «Татарча-урысча сүзлек» | 1927, Казань | яңа имля, двуязычный словарь | 4 / 4 | 2 382 | не вычитано |
| `commons_bukvar_1912_photo` | Курбангалиев, букварь (музейное фото) | 1912, Казань | иске имля | — (unlabeled) | — | GT нет |

Итого: **45 размеченных страниц, 3 источника, 16 617 арабских букв** (+17 740 кириллических — русские
переводы в словарных страницах). Все размеченные страницы — `split=test`: в Phase 1 нет обучения, поэтому
train/val не нужны; новые источники для обучения будут добавляться **другими** `source_id`.

Подмножества: `core` = 18 страниц (почти чистая арабица) — основная таблица сравнения;
`mixed` = 27 страниц (списки «татарское слово — русский перевод»), для них основная метрика — `arabic-only CER`.

### Ограничения GT (важно для интерпретации CER)
* **Неполные транскрипции:** у 3 страниц словаря 1927 г. (13, 15, 225) Wikisource покрывает только часть
  страницы — они помечены `silver_partial` (`data/gt_overrides.yaml`) и не участвуют в метриках
  (оцениваемых страниц: 42).
* «Silver»: 43 из 45 страниц на Wikisource не вычитаны → часть «ошибок» моделей может быть ошибками GT.
  62 места помечены транскрибентами как сомнительные (`{{?|…}}`).
* Нумерация списков `<ol>` в вики-разметке не попадает в GT (а на странице напечатано, например, «١)») —
  систематическая мелкая «ошибка» вставки у всех моделей.
* Порядок строк в двухколоночных словарных страницах задан вики-разметкой (по ячейкам), а не реальным
  визуальным порядком; это штрафует WER/CER, но не BoW-F1.
* Транскрибенты 1920-х гг. используют спецзнаки яңа имля (напр. U+08AD `ࢭ`, `ىُ` с дамма), которых нет
  в словарях ни одной из моделей → нижняя граница CER > 0 для всех моделей на этих страницах.

### Правила конверсии вики-разметки → GT (версия 2, `src/benchmark/wikisource.py`)
* удаляются `<noinclude>` (служебные заголовки) и HTML-комментарии;
* `{{ditto}}` → `〃`; `{{?|X}}` → `X` (место записывается в `uncertain_spans`); `{{SIC|как напечатано|исправление}}` →
  *как напечатано*; `{{lang|tt|X}}` → `X`; форматирующие обёртки (`{{c}}`, `{{uc}}`, `{{font-size}}`…) → содержимое;
  `{{tt/икетелле сүзлек|…}}` и вики-таблицы → по одной ячейке/строке таблицы на строку;
* HTML-сущности раскрываются (`&zwnj;` → ZWNJ U+200C), `<br>` и блочные теги → перевод строки;
* маркеры списков `*#:` и разметка ссылок/жирного удаляются; буквы, ZWNJ, пунктуация и цифры не меняются.

## 2a. Phase 2: старотатарский датасет

### Модель данных (что хранится на страницу)

| элемент ТЗ | где |
|---|---|
| page image | `data/raw/<source_id>/pNNNN.jpg` (не в git; восстанавливается скриптами по закреплённым URL, sha256 в `page_meta/` или GT-метаданных) |
| line polygon / bbox, baseline, порядок | PAGE XML версии GT: `data/gt_history/<page_id>/vNNN.page.xml` |
| line image | генерируется `scripts/export_lines.py` → `data/processed/lines/<split>/*.png` + `lines.jsonl` |
| точная транскрипция арабицей | `data/gt_history/<page_id>/vNNN.txt`; текущая — `data/ground_truth/<page_id>.txt` |
| современная кириллица | `data/ground_truth/<page_id>.modern_tatar.txt` (если есть) |
| метаданные источника: год, издатель, документ, шрифт/стиль, печать/рукопись, писец, источник, лицензия | `data/sources.yaml` (проверка: `python -m benchmark.sources validate`) |

**Версии GT** (`python -m benchmark.gt_store …`): каждая правка — новая неизменяемая версия с автором, временем,
источником и CER к предыдущей; машинные черновики (`draft_unverified`) хранятся для истории, но никогда не
становятся GT. Импорт Wikisource не перезаписывает исправленные людьми версии.

**Семейства источников** (`family` в `sources.yaml`): серия/типография/писец. Семейство целиком принадлежит
одному сплиту. Пример: книги 02–10 серии «Татар мәктәбе» (1914–16, та же типография Хусаинова) нельзя класть в
train, пока книга 01 серии — в test; их можно добавлять только в test.

### Инструменты

| шаг | команда |
|---|---|
| каталог кандидатов на Commons | `python scripts/catalog_commons.py` → `data/candidates/commons_tatar.csv` |

| импорт исправленного | `python scripts/import_annotations.py export/*.xml --status silver_proofread --author …` |

## 3. Политика разбиения
Разбиение train/val/test — **только по `source_id`**. Страницы одной книги/рукописи/номера газеты никогда
не попадают в разные сплиты (валидатор манифеста это запрещает). Тест на этапах 2–3 — только реальные
старотатарские документы; синтетика допускается лишь в train (pretraining).

## 4. Какая человеческая разметка нужна (labels не выдумываются)

Минимум для честного baseline и первого fine-tuning, в порядке приоритета:

1. **Вычитка существующего silver GT (≈ 45 стр.)** до `gold_verified`: сверить с изображением, особенно
   43 невычитанные страницы и 62 сомнительных места; восстановить пропущенную нумерацию списков.
   Объём: ~45 страниц × 10–20 мин.
2. **Рукописный тест-сет (сейчас 0 страниц!)**: 30–50 страниц из ≥ 5 разных рукописных источников
   (письма, метрические книги мечетей, шәҗәрә, рукописные книги), с указанием писца/источника/лицензии.
   Без него на вопрос «print vs handwriting» ответить нельзя.
3. **Печать других типографий и жанров** (газеты «Вакыт», «Йолдыз», журнал «Шура», казанские издания
   1900–1917): ≥ 10 источников × 5 страниц для test + отдельные источники для train.
4. **Построчная разметка** (полигон/baseline строки + текст строки) — нужна для fine-tuning line-распознавателей
   (kraken/PP-OCRv6) и для `exact_line_accuracy`. Рекомендуемый инструмент — eScriptorium
   (импорт сегментации kraken, экспорт ALTO/PAGE). Ориентир по объёму для дообучения печати:
   2–5 тыс. строк из ≥ 10 источников (OpenITI-модели обучались на 7–23 тыс. строк на язык).
5. **Параллельная современная кириллица** для части страниц (14 страниц уже есть с Wikisource) — для Phase 4.

Правила транскрипции для разметчиков (согласовать с филологом до начала работ):
* буквально, как напечатано, включая опечатки (исправления — в отдельном поле);
* сохранять ZWNJ там, где буквы явно не соединены внутри слова;
* сохранять огласовки, хамзу, цифры в исходной форме (арабско-индийские или европейские);
* одна строка изображения = одна строка текста; переносы слов не склеивать;
* нечитаемое: `[?]`, сомнительное чтение: `[?:вариант]`; иноязычные вставки (русский, арабский) — как есть.
